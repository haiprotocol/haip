---
title: 'CLI commands'
description: 'Arguments, output files and verification limits for the draft CLI.'
---

Run these commands through `node haip-cli/dist/index.js` from a built checkout, or through the `haip` binary from an explicitly installed draft package.

| Command                                                        | Behaviour                                                                                            |
| -------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------- |
| `help` or `--help`                                             | Print available commands; no credential is needed.                                                   |
| `create <request.json> <idempotency-key>`                      | Submit one immutable request. The explicit key is required.                                          |
| `status <request-id>`                                          | Read current scoped status.                                                                          |
| `cancel <request-id> <idempotency-key>`                        | Request cancellation with a stable operation key.                                                    |
| `events [after-cursor]`                                        | Read signed events; the omitted cursor defaults to zero.                                             |
| `export <request-id> <output.json>`                            | Write retained audit evidence to a new private file. It never overwrites an existing file.           |
| `verify <record.json> <trust.json> <issuer> <audience> <type>` | Verify an original signed record against independently supplied trust and expected signing identity. |

Server failures print the HTTP status and error code to standard error and set a non-zero exit status. Successful read and mutation commands print JSON, except export and verification, which print a result message.

Keep the same creation or cancellation key when retrying the same logical operation. Save an event cursor only after durable processing. Store exports as private material and respect retention policies.

`verify` is an offline signature/identity check. It does not establish complete historical time, human understanding, current execution authority or an external effect's outcome. An executor needs the full [execution verification flow](/sdk/execution).
