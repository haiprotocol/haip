---
title: "CLI \u2014 quickstart"
---

The CLI uses the same public HTTP protocol and separate producer credentials. Set `HAIP_URL` and `HAIP_TOKEN`; explicitly set `HAIP_LOCAL_HTTP=true` only for a localhost fixture. Build before running `node haip-cli/dist/index.js`.

```sh
haip create request.json stable-idempotency-key
haip status REQUEST_ID
haip events AFTER_CURSOR
haip cancel REQUEST_ID stable-cancellation-key
haip export REQUEST_ID audit.json
haip verify record.json trusted-manifest.json ISSUER AUDIENCE RECORD_TYPE
```

Creation requires an explicit stable idempotency key. Retrying the same key with changed input fails. `events` returns a `next` cursor; persist it after handling the page. Exports use exclusive file creation with private permissions and never overwrite an existing export.

`verify` authenticates a signed record against independently supplied trust and expected signing identity. It does not prove complete audit history, completion or current execution authority. The CLI does not approve requests; open the review link and confirm through the authenticated browser.

HAIP 1 streaming/chat commands are archived and are not compatibility aliases for HAIP 2.
