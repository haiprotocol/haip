---
title: "Try HAIP 2"
---

HAIP accepts an immutable request, presents it to an authenticated person and returns a signed decision. A review response never grants execution authority.

From a checkout with Node 24 and PostgreSQL 17 installed:

```sh
npm ci
npm run build
npm run demo
```

The demo prints a loopback origin and random fixture credentials. It runs a temporary PostgreSQL database, local identity provider and explicitly non-production anchor. Keep it local. Its data is removed on normal shutdown.

In another terminal, set `HAIP_URL` to that origin, `HAIP_TOKEN` to its producer credential, `HAIP_LOCAL_HTTP=true` and a stable `HAIP_IDEMPOTENCY_KEY`. Run:

```sh
node examples/http/review.mjs
```

Open the returned review link, sign in as `reviewer`, inspect the retained document and payload, propose a response, then press **Confirm this exact response** in the trusted host. Fetch status using the producer credential. The signed receipt commits to the exact response; use the export to obtain retained response bytes.

For an optional independent App, run `npm run example:app`, set the separate `HAIP_PUBLISHER_TOKEN`, and run `node examples/http/register-app.mjs`. Set its returned ID as `HAIP_BUNDLE_ID` for a new review request. The producer must be mapped to that publisher by the operator.

For deployment, replace every fixture dependency with the explicitly configured services in [deployment](/server/deployment). No default or demo credentials are suitable for production.
