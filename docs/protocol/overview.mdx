---
title: "Protocol and authority"
---

HAIP is an independent MIT protocol. JSON Schema, OpenAPI 3.1 and generated types define `2.0.0-draft.1`. Unsupported revisions or required profiles fail; they are never silently ignored. Unknown metadata remains signed and non-authorising.

| Purpose | Result | Execution authority |
|---|---|---|
| `review` | Structured response and signed receipt | Never |
| `authorise_execution` | Explicit human decision plus an execution binding | Requires anchored grant, exclusive claim and fresh admission |

Requests capture tenant, producer, operator-mapped requester, route revision, artefact/payload/schema/document digests, optional bundle, purpose, profiles, limits and deadlines. Execution adds a stable occurrence, proposal/context/policy commitments, mode, provenance and a service authority namespace.

A candidate freezes the exact response. Confirmation identifies both its ID and digest. Changing a candidate invalidates the earlier confirmation target. Producer credentials and App tools cannot confirm.

Decision, audit, grant and execution states are separate. A signature authenticates a record; it does not prove understanding, correctness, dispatch or completion. Human review is oversight, not an execution engine.

Only `haip.execution=1-draft.1` and the optional `haip.mcp-app=1-draft.1` are advertised. The Plasm profile remains a set of externally owned integration requirements. Full HAIP 2 release gates are tracked separately from the working HAIP-owned implementation.
