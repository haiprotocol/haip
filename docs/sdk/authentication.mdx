---
title: "SDK \u2014 authentication"
---

Machine bearer credentials identify producers, publishers or operators. Publishers register their own immutable bundles; producers can reference only their mapped publisher. Operators configure routes and verified workload owners. A producer-provided name never establishes human identity.

Humans sign in through OIDC authorization code flow with PKCE, state and nonce. The issuer/subject pair must map to exactly one enabled operator-directory entry. Sessions are held on the server and use Secure, HttpOnly, host-only SameSite cookies. Human writes also require the session CSRF token and the exact trusted Origin.

A human proposes a schema-valid candidate and separately confirms its exact ID and digest. Apps can call only `haip_propose_decision`; they cannot read cookies, obtain bearer credentials or confirm. Production routes require separation between requester and reviewer. Uncertain identity temporarily prevents authority; it does not silently waive the check.

Disabling a reviewer or removing them from a route invalidates their affected grants. Re-adding them does not restore those grants. Unrelated membership changes preserve other reviewers’ grants. Authorising rule changes advance the route revision.

Rotate machine tokens on the same stable principal ID to preserve quotas. Never recycle a human ID for another OIDC subject. Recovery disables all old credentials and requires explicit reprovisioning.
