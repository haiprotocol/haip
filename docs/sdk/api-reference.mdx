---
title: 'SDK method reference'
description: 'The public client methods and their result boundaries.'
---

`HAIPClient` sends canonical JSON, follows no redirects and uses a 15-second request timeout. Successful responses are decoded with the protocol JSON parser. Non-success HTTP responses raise `HAIPError`; transport or decoding errors can be ordinary errors.

| Method                       | Result and requirements                                                                                  |
| ---------------------------- | -------------------------------------------------------------------------------------------------------- |
| `create(input, key)`         | Accepted `RequestStatus`; provide a stable creation key.                                                 |
| `status(id)`                 | Current scoped `RequestStatus`.                                                                          |
| `cancel(id, key)`            | Updated status after an authorised cancellation.                                                         |
| `events(after = 0)`          | Signed event `items` and the next cursor. Persist processing before advancing.                           |
| `audit(id)`                  | Retained request evidence and response material, subject to access and retention.                        |
| `claim(id, input, key)`      | Signed exclusive execution claim for the supplied stable identity and binding.                           |
| `admission(id, claim)`       | Signed fresh admission, nonce and local wall/monotonic timing observations.                              |
| `outcome(id, input, key)`    | Signed outcome record. Reporting must not repeat an effect.                                              |
| `request(path, body?, key?)` | Low-level access limited to `/v2/` and `/.well-known/` paths; normal server authorisation still applies. |

`verifyRecord` authenticates an original signed record against independently supplied trust and expected identity. It is not a substitute for the complete [execution verifier](/sdk/execution).

```ts
const page = await client.events(savedCursor);
await persistEvents(page.items); // Your durable consumer implementation.
await saveCursor(page.next);
```

The consumer functions are application responsibilities, not SDK exports. Re-fetch request status when acting on an event; never launch work solely because an event says it was authorised.

Only `create`, `cancel`, `claim` and `outcome` take explicit idempotency keys in these convenience methods. `admission` generates a fresh nonce for each check and does not extend the original dispatch deadline.
