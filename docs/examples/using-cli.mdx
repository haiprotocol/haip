---
title: 'Review from the CLI'
description: 'Submit the fixed example, confirm in the browser and retrieve its evidence.'
---

Build the checkout and start `npm run demo` as described in the [local walkthrough](/quickstart). In another private terminal set the printed origin and producer credential as `HAIP_URL` and `HAIP_TOKEN`, with `HAIP_LOCAL_HTTP=true`.

Create the repository's fixed review request. Keep the same key if this command loses its response and needs retrying:

```sh
node haip-cli/dist/index.js create examples/http/review.json cli-review-1
```

Copy the returned request ID for subsequent commands. Open its review link in a browser, sign in as `reviewer`, inspect the stored material and confirm an exact response. The CLI does not carry out that confirmation.

```sh
node haip-cli/dist/index.js status REQUEST_ID
node haip-cli/dist/index.js events 0
node haip-cli/dist/index.js export REQUEST_ID review-audit.json
```

The status separates decision, audit, grant and execution state. For this review-only example, grant and execution are not applicable even when the person chooses accept. The export uses private permissions and refuses to overwrite an existing file.

Persist the returned event cursor after processing its page. A notification is not execution authority; fetch current status when using it. Keep exported material private and remove the disposable fixture after the walkthrough.

The [command reference](/cli/commands) also covers cancellation and offline verification. The old streaming/chat CLI example remains in the [HAIP 1 archive](/archive/v1/examples/using-cli).
