---
title: "Monitoring and incidents"
---

Use `GET /v2/admin/metrics` for scoped JSON or `GET /v2/admin/metrics.prom` for Prometheus. Authenticate with the tenant operator credential. Responses include request volume, pending age, reviewer pressure, retained bytes, unresolved execution, delivery state and checkpoint lag. HTTP counters reset on process restart; database gauges survive it.

Alert on admission fencing, delivery failures, checkpoint lag beyond five minutes, missing retention runs beyond 30 minutes and unresolved executions past their captured window. Worker success/failure timestamps are exposed in JSON and Prometheus. Adjust reviewer-pressure thresholds to staffing. Configuration examples in `deployment/alerts.yml` are not installed automatically.

Inspect `GET /v2/admin/ledger?after=<sequence>` for the tenant’s original audit records. Request status includes delivery attempts and safe failure codes. SMTP acceptance is not proof of delivery or reading. Keep responses, email addresses and credentials out of alert labels.

Checkpoint conflicts or unexpected object versions require incident investigation. Do not delete remote versions to clear the alarm. Missing effects remain uncertain; operators may reconcile only with reasons and independently established evidence. Reconciliation never refunds a consumed occurrence.

External executors must supply policy, destination, credential, evidence-storage and dispatch-window monitoring. HAIP cannot observe hidden external effects.
