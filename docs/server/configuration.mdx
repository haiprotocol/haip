---
title: "Configuration and captured limits"
---

The full environment-variable reference is in `OPERATIONS.md`. Required settings include the database URL, exact trusted and sandbox origins, Ed25519 signing key and key ID, independent trust manifest and OIDC client configuration. SMTP and webhook destinations are optional; no callback URLs are accepted in individual requests.

| Limit | Default |
|---|---|
| Bundle / payload / response | 5 MiB / 10 MiB / 256 KiB |
| Inline App result | 2 MiB; larger payloads stay in the trusted host view |
| Retained material | 1 GiB per producer |
| Producer creation | 10/minute, burst 20; 200/day; 100 outstanding |
| Tenant creation | 50/minute, burst 100; 1,000/day; 500 outstanding |
| Route creation | 100/day |
| Email / reminders | 10 per recipient/hour; one reminder/request/day |

Routes may reduce limits, never increase the reference maxima. Requests capture their limits; later configuration does not renew deadlines. Credentials, reassignment and supersession do not reset identity-based quotas. The first response slot is reserved at creation so existing work can still be resolved at quota.

Review and grant defaults are 24 hours each, execution one hour, private reconciliation seven days and audit retention 90 days. The absolute execution-private cap is nine days and one hour from acceptance. Cleanup runs every 15 minutes; reads reject expired material immediately.
