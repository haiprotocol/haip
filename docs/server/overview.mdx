---
title: "Reference service"
---

The reference service uses Node 24, Express 5 and PostgreSQL. Tenant transactions serialize authority changes and read PostgreSQL UTC after acquiring the lock. Decisions, signed events and outbox jobs commit together.

The native inbox provides pending/history filters, assignment, full retained documents, searchable payload fields, deadlines, separate authority states and delivery failures. A host response form always remains available when an optional App fails.

Operator-managed directory entries separate producers, publishers and OIDC humans. Each producer has an owner, allowed routes and one optional webhook destination. Verified owners receive notifications after the original agent session ends. Without SMTP the service explicitly reports polling-only operation.

Independent Azure Blob checkpoints hold execution grants pending until accepted. Permanent safety records prevent namespace and occurrence reuse after restart or restoration. Production has no transparent failover: one process owns a generation, and a restart requires recovery and fresh provisioning.

The runtime does not contain Plasm code, continuation reconstruction, live credentials or a general executor. See [deployment](/server/deployment), [monitoring](/server/monitoring) and [authentication](/server/authentication).
