---
title: 'Identity and trusted confirmation'
description: 'Separate machine credentials from the person who confirms the decision.'
---

Machine bearer credentials identify producers, publishers or operators, each with a stable principal ID and tenant. They are not human sessions and cannot confirm decisions. A name supplied in a request never establishes a person's identity or ownership.

Humans sign in through the OIDC authorisation-code flow with PKCE, state and nonce. The issuer/subject pair must map to exactly one enabled operator-directory entry. Login consumes one-use callback state and rotates the server-side session. Cookies are Secure, HttpOnly and host-only; they are not App credentials.

Human mutations require the authenticated browser session, a session CSRF token and the exact trusted Origin. Review links only locate resources; possessing a link, digest or App registration does not grant payload access or confirmation rights.

A person proposes a schema-valid response and separately confirms that candidate's exact ID and digest. Replacing the proposal invalidates the previous confirmation target. An App can propose through `haip_propose_decision`, but the host retains the confirmation step.

Production requires separate registrable sites for the trusted host and sandbox. Different sibling subdomains alone do not provide that boundary. Each tenant/publisher/bundle receives its own sandbox origin, with a scripts-only opaque inner frame and no arbitrary host operations.

Routes require verified requester/reviewer separation. Directory aliases of the same OIDC identity cannot satisfy self-review separation. Uncertain identity blocks authority; disabling or removing a reviewer permanently invalidates affected grants, and re-adding the reviewer does not restore them.

Rotate machine tokens on the same principal ID to preserve ownership and quotas. Never recycle a human ID for a different issuer/subject pair. Recovery disables old credentials and requires explicit reprovisioning. A real Clerk or Entra application still needs isolated deployment acceptance; the local OIDC fixture does not prove a provider configuration.
