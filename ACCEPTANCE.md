# Acceptance matrix

This maps the agreed plan to concrete evidence. **Local** means the HAIP-owned implementation is exercised by isolated fixtures, locally or in hosted CI. It does not certify a deployed system. **External** marks evidence that must come from real infrastructure or an accountable party outside the implementation team. **Downstream** identifies Plasm work needed only for a corresponding Plasm integration claim. Contracts remain draft. Original results and source hashes are in `research/haip2-2026-08-30/validation/manifest.json`.

The first hosted run passed 46 tests and 25 comparisons across languages. Its versions, tested commit and retained artefacts are in the [remote CI record](research/haip2-2026-08-30/validation/remote-ci-33334308802/manifest.json). The [review follow-up](REVIEW-FIXES.md) records the subsequent safety fixes, clean checkout and hosted suites with 68 tests, plus nine development container checks. [New evidence](research/haip2-2026-08-30/validation/review-fixes-bc1feed/README.md) is retained separately. Historical records are not overwritten by later runs. The [worker and boundary follow-up](WORKER-FOLLOW-UP.md) records the subsequent maintenance bounds, export, pagination, login and browser changes. Its [separate evidence](research/haip2-2026-08-30/validation/worker-follow-up-7daeefa/README.md) records 85 passing tests, 25 comparisons and nine container checks on `7daeefa`.

The [Agent UI run](https://github.com/haiprotocol/haip/actions/runs/33811067004) tested draft 3 at `c39eb20ac8707e0b3ddafabfb3edc201a992a80c`. Its results and limits are recorded in [the implementation ledger](IMPLEMENTATION.md), while the required PR check governs later changes.

This assurance work adds an internally authored Python 3.9 client using only the standard library, current contract binding before Quint, CodeQL analysis, request rate controls, protection for backup credentials passed to child processes and deployment acceptance assets. The review PR's required checks govern its final revision. Independent implementation and security review, followed by real deployment and recovery acceptance, remain open.

The filesystem safety store is a fixture for fault injection and does not provide production WORM. Azure adapter tests do not contact Azure, and the Bicep template has not been provisioned. The OIDC fixture is not a Clerk account. The counter and Python client are bounded, internally authored demonstrations. The acceptance runner records evidence supplied by trusted operator adapters, so its report does not replace independent administration or inspection. No external or downstream boundary is marked complete by substituting one of these fixtures.
