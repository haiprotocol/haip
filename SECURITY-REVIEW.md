# Security review

## Status

This record covers an internal source review of HAIP 2 draft 3 on 4 September 2026, based on commit `71730f0a088c43faa0351da68fea4fe1d56ae901` plus the resolved changes listed below.

Reviewed implementation revision: `dbfd04c9b508bd45938a18231a6e3f3dd539dce6`.

No unresolved critical or high severity source defect was found in the reviewed scope after the fixes in this change. Three medium risks remain across runtime availability, secret operations and reviewer persuasion, with one low risk in the local counter fixture. Provider acceptance and independent review remain release work.

## Boundary

This is preparation by the implementation team. It does not satisfy the independent security review requirement, certify a production deployment or establish that a separately accountable implementation agrees with the protocol.

The review covers this repository's HAIP 2 protocol implementation, server, browser host and sandbox, SDK verification, CLI, migrations, tests and GitHub security workflow. Historical material under `archive/`, research records, generated output and third-party services are outside the source verdict.

Live provider permissions, identity federation, email delivery, external webhook ownership, operational key rotation, recovery by a second operator and production capacity were not exercised here.

## Method

The reading pass traced authentication, authorisation, tenant selection, parsing, quotas, state changes, signed records, audit anchoring, recovery, backup and restore, outbound network calls, browser messages and execution admission from each external entry point to its effect.

The automated pass used the CodeQL JavaScript `security-extended` suite, a focused missing rate limiting query, the TypeScript build, real PostgreSQL backup and restore coverage, focused regression tests and the generated OpenAPI consistency check.

The companion threat model records the assets, trust boundaries, attacker capabilities and abuse paths used for this review.

## Resolved

| ID     | Severity | Finding                                                                                                                                                                                                             | Resolution                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            |
| ------ | -------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| SR-001 | High     | `pg_dump` and `pg_restore` received the configured database URL in argv, exposing its password to process inspection on affected hosts.                                                                             | `haip-server/src/backup.ts` now removes the database password and `sslpassword` from argv, refuses URI parameters that select another passfile or libpq service, writes the database password to a host, port, database and user specific libpq passfile with mode `0600`, passes a TLS key password through a scrubbed child environment when configured, removes inherited database, password, passfile and service variables, preserves public connection parameters and removes the temporary directory after child exit or launch failure. The regression covers URI override refusal, decoding a query password once, passfile identity, argv, inherited variables and cleanup. |
| SR-002 | Medium   | Authentication, health and API database work had quotas at the protocol layer but lacked an application admission limit, which left cheap repeated requests able to consume database or identity-provider capacity. | `express-rate-limit` is pinned exactly. Login and callback share a 120 request per minute service bucket, protected credential paths share a 12,000 request per minute service bucket, health has a 600 request per minute service bucket and authenticated API handlers share a 1,200 request per minute tenant and principal bucket before preflight and body parsing. Repeated route references to the same limiter are idempotent for one request, and JSON tuple keys keep tenant and principal identifiers unambiguous. The aggregate buckets reflect Caddy as the direct peer and make no client IP claim.                                                                     |
| SR-003 | Low      | The OpenAPI generator used alternation with only its final branch anchored, which was correct for the fixed path list but easy to misread or extend incorrectly.                                                    | `scripts/openapi.mjs` now groups and anchors the complete human-route expression.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| SR-004 | Medium   | Acceptance adapters inherited the operator process's complete environment even when the plan named a narrower credential set. An adapter could receive unrelated ambient credentials.                               | The acceptance plan now declares every inherited variable in `adapter_env`, with every `secret_env` entry required to be a member. Adapters receive only those defined values, `PATH` when present and the generated check ID. Reports list inherited names, tests prove an unrelated secret is absent, and the runbook still treats adapters as trusted code with the operator's filesystem authority.                                                                                                                                                                                                                                                                               |
| SR-005 | Medium   | Checkpoint, webhook and SMTP network calls ran while the worker held the tenant advisory transaction lock, allowing a slow dependency to delay confirmation and other tenant writes.                                | Migration 007 adds durable generation and revision claims with five-minute leases and claim-aware ready indexes. The worker now claims in a short transaction, performs bounded network I/O after commit and finalises under the tenant lock only when the stored generation and revision still match. Tests cover concurrent exclusion, abandoned-claim recovery, retry, index use, migration and destination changes during successful and failed delivery.                                                                                                                                                                                                                         |

## Controls

| Area      | Evidence                                                                                                                                                                                                                                                                                                                                                                                          | Result                                                                                                                                      |
| --------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------- |
| Identity  | `haip-server/src/auth.ts` uses OIDC discovery, PKCE, nonce, state, binding to the browser's initiating session, hashed server sessions, secure host cookies and CSRF checks on state-changing human requests. Bearer tokens are stored as digests and reloaded from the tenant principal record.                                                                                                  | Present, with identity-provider and token custody left to deployment controls.                                                              |
| Tenancy   | `haip-server/src/service.ts` reloads principals inside tenant transactions, scopes object reads by tenant and returns the same absence response for unavailable objects. PostgreSQL calls use parameters.                                                                                                                                                                                         | No cross-tenant object path was found in the reviewed flows.                                                                                |
| Parsing   | `haip-server/src/server.ts` authenticates protected paths before the bounded raw JSON parsers, refuses compression and non-UTF-8 bodies, and uses the strict protocol parser. Protocol quotas cover payload, schema, response, bundle and retained bytes.                                                                                                                                         | Present. Service-wide request admission now runs before protected parsing.                                                                  |
| Decisions | Candidate creation validates purpose, decision, schema and response size. Confirmation accepts only the current candidate ID and digest for the same reviewer under the tenant lock. The trusted browser displays the complete frozen candidate before a trusted gesture.                                                                                                                         | The earlier candidate replacement race remains closed.                                                                                      |
| Browser   | The host and producer View use separate registrable sites. The producer code runs in an opaque inner frame behind a trusted proxy with a restrictive CSP, exact message shapes, byte and depth limits, request ID tracking, source checks and exact outer origin checks.                                                                                                                          | Producer code can present and propose. It cannot confirm or call the service directly through the bridge.                                   |
| Execution | Purpose, profile, proposal, context, policy, occurrence, execution identity, claim, admission, receipt, checkpoint and time bounds are verified before dispatch. Permanent recovery records prevent a restored database from reopening consumed occurrences or retired generations.                                                                                                               | Present in the reference SDK and fixed counter demonstration. Another executor still needs its own conformance evidence.                    |
| Audit     | Audit records form a hash chain and signed checkpoints are accepted only after checks of the exact immutable version and retention. Production startup requires checkpoint and safety storage plus an explicit assertion of independent administration.                                                                                                                                           | Source controls are present. Real account policy and administrative separation still need acceptance evidence.                              |
| Outbound  | Webhooks require an exact configured hostname, HTTPS on port 443, no URL credentials or fragment, public results for every DNS answer and a pinned selected address. Redirects are not followed. SMTP disables file and URL access. Durable generation and revision claims keep network waits outside the tenant transaction and prevent a failed send from retrying after its authority changes. | No direct server-side request forgery path was found in the reviewed delivery flow. SMTP acceptance remains a best-effort transport result. |
| Recovery  | Restore authenticates the complete encrypted backup before `pg_restore`, requires an empty target, fences admission and retires the old generation through separate permanent records. Backup files use mode `0600`.                                                                                                                                                                              | Present, including the argv credential fix. Offline procedure and key custody remain operator duties.                                       |
| Supply    | Runtime dependencies are exact versions. The CodeQL workflow and checkout action use full commit SHAs, minimal permissions and source exclusions for archives and generated bundles.                                                                                                                                                                                                              | Present. `npm audit --omit=dev` reported zero production dependency vulnerabilities for the reviewed revision.                              |

## Open risks

| ID     | Rating | Risk                                                                                                                                                                                                                                                    | Required treatment                                                                                                                                                                                                                  |
| ------ | ------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| SR-R02 | Medium | Request admission uses in-process memory. It resets on restart and each process has its own counters. The unauthenticated buckets are deliberately service-wide because Caddy is the direct peer, so one noisy client can consume the shared allowance. | Keep the current aggregate circuit breaker, add limits per client at the trusted edge, and use a shared store before running more than one service process. Prove expected limits with load tests that use the production topology. |
| SR-R03 | Medium | Signing, OIDC, database, SMTP, backup and bearer credentials depend on runtime secret custody and an operator rotation process. Source validation prevents several configuration errors but cannot prove access policy or timely rotation.              | Exercise issuance, revocation and recovery with production identities, record owners and expiry dates, and keep signing, recovery and database authority separately administered.                                                   |
| SR-R04 | Medium | A producer View can use layout and language to persuade a reviewer even though it cannot perform confirmation. The trusted panel for the exact candidate contains the authoritative content, but the decision still depends on human attention.         | Retain the native view, clear producer provenance and complete candidate display. Include deceptive content in user testing and independent review.                                                                                 |
| SR-R05 | Low    | The fixed counter demonstration assumes its local directory is private to its operator. A process with the same filesystem authority can race or replace local state around the durable fence operations.                                               | Keep the example out of shared writable directories and treat a production executor as a separate security review target.                                                                                                           |

## CodeQL

The final local `security-extended` run used query pack `codeql/javascript-queries@2.2.4` and returned 13 results in maintained paths, all accepted with the reasons below. An earlier run identified SR-003. A fresh focused run returned zero `js/missing-rate-limiting` results after SR-002.

| Query                     | Count | Triage                                                                                                                                                                                                                                                                                                     |
| ------------------------- | ----: | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `js/reflected-xss`        |     1 | `tests/fixtures/oidc.ts` is an isolated identity-provider fixture. Its value enters a double-quoted attribute after escaping `&`, `"` and `<`. CodeQL does not recognise the local escape function.                                                                                                        |
| `js/file-access-to-http`  |     4 | Two explicit HTTP examples send local JSON or HTML selected by the operator to an independently configured HTTPS origin. Two tests replace DNS and HTTPS transport with isolated listeners. File content does not select the destination in these paths.                                                   |
| `js/file-system-race`     |     5 | Four results belong to the fixed counter example, where exclusive file creation provides the authority fence and the directory is operator controlled. One belongs to the intentionally small filesystem anchor used only in tests. Neither implementation is a production service on a shared filesystem. |
| `js/missing-origin-check` |     1 | `tests/browser.test.ts` installs an observer to record a deliberately forged message. The observer performs no privileged action and exists to prove that the production host rejects the message.                                                                                                         |
| `js/http-to-file-access`  |     2 | The CLI audit command writes the requested remote export to an explicit operator path with exclusive creation and mode `0600`. The other result is a test that creates a counter refusal fixture. Remote content does not choose either path.                                                              |

An earlier local alert in ignored `haip-server/public/host.js` traced to a stale generated bundle containing old Zod code. The reviewed source is `haip-server/src/browser/host.ts`. `.github/codeql-config.yml` excludes archived, research, output, distribution and generated browser bundles so the workflow analyses maintained source.

`SCAN_DIR` was a new directory created with `mktemp -d /tmp/haip-codeql.XXXXXX`. Results from the broad local database were filtered using the same paths listed in `.github/codeql-config.yml` before triage.
